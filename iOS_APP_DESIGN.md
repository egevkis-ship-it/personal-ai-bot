# Фитнес-приложение для iPhone на базе бота — дизайн-документ

Версия 1.0 · черновик для обсуждения. Объём первой версии: **только фитнес-модуль**.

---

## 1. Главная идея

Сейчас вся логика живёт в Telegram-боте на Python (aiogram). Бот уже умеет всё, что нужно приложению:

- запись тренировки с разбором свободного текста («Жим штанги 80×10», суперсеты, разминка, «до отказа», время для планки) и голосом (Whisper);
- планы тренировок (на день/неделю), в т.ч. сгенерированные ИИ;
- история тренировок за период;
- замеры тела (вес, икра, бедро, ягодицы, живот, талия, грудь, рука, шея);
- фото-прогресс с ИИ-анализом и сериями;
- отчёты за период в PDF;
- ИИ-«тренер»: после тренировки даёт короткое резюме (тоннаж, динамика, прогресс по упражнениям).

**Ключевое архитектурное решение:** не переписываем логику на Swift. Вместо этого выносим существующий Python-код в HTTP API, а приложение делаем тонким клиентом поверх него. Бот и приложение работают с одной базой — данные общие.

```
                ┌─────────────────────────┐
                │     iPhone-приложение     │  ← новый тонкий клиент
                │   (экраны, ввод, графики) │
                └───────────┬─────────────┘
                            │ HTTPS / JSON
                ┌───────────▼─────────────┐
                │   API-слой (FastAPI)     │  ← новый, тонкая обёртка
                ├──────────────────────────┤
                │  Существующая логика:     │  ← переиспользуем как есть
                │  set_parser, planner,     │
                │  coach, report_builder,   │
                │  photo_vision, db/...     │
                └───────────┬─────────────┘
                            │
              ┌─────────────┴─────────────┐
              │   PostgreSQL  ·  Redis     │  ← та же база, что у бота
              └────────────────────────────┘
                            ▲
                ┌───────────┴─────────────┐
                │   Telegram-бот (aiogram) │  ← продолжает работать
                └──────────────────────────┘
```

Плюсы: один источник правды, переиспользуем 90% кода, бот и приложение не конфликтуют, ИИ-функции уже готовы. Логика разбора текста (`set_parser`, `measurement_parser`) вообще не зависит от Telegram — её можно дёргать напрямую.

## 2. Выбор технологии клиента (решение отложено)

Мы договорились спроектировать сначала, а технологию выбрать потом. Три реальных варианта:

| | Нативное SwiftUI | React Native / Expo | PWA (веб на iPhone) |
|---|---|---|---|
| Качество/ощущение | максимальное | хорошее | среднее |
| Нужен ли Mac + Xcode | да | для финальной сборки | нет |
| Скорость до первого запуска | средняя | быстрая (Expo Go) | мгновенная |
| Камера/фото, графики | отлично | хорошо | ограниченно (но работает) |
| Публикация в App Store | да | да | нет (только иконка на экране) |
| Голосовой ввод | нативный | через плагин | ограниченно |

Рекомендация под этот проект: **начать с PWA или Expo** как быстрый рабочий прототип на одном API, а на нативный SwiftUI перейти, если захочется максимального качества и App Store. API-слой при любом выборе один и тот же — он не пропадёт.

Стоимость публикации в App Store: **$99/год** (Apple Developer Program). Это единственный обязательный платёж. Для личного использования можно вообще не платить — приложение ставится на свой iPhone бесплатно через Xcode.

## 3. Карта экранов (фитнес)

### 3.1 Онбординг / вход
- Вход по тому же аккаунту, что и бот (привязка к Telegram user id или отдельный токен — см. §5).
- Один раз: выбор часового пояса (в боте это уже есть в «Сервис»).

### 3.2 Дашборд (главный экран)
Главная — это точка быстрых **действий**, а не витрина статистики. Поэтому вместо «веса» и «числа тренировок» (их место — в разделах «Замеры» и «История») здесь:

- крупная кнопка сегодняшней тренировки: «Начать тренировку по плану» (или «Продолжить», если есть активная сессия);
- сетка быстрых действий 2×2: **Записать замер**, **Добавить фото**, **Повторить прошлую тренировку**, **Мои планы**;
- внизу — таб-бар навигации (Главная · Тренировка · Замеры · Фото · История).

Статистику и графики оставляем внутри профильных разделов, чтобы главный экран был коротким и про «что сделать сейчас».

### 3.3 Тренировка
- **Старт.** Экран «что тренируем» с вариантами:
  - **По плану на сегодня** (основной);
  - **Другой день недели** — можно взять любую тренировку плана этой недели, даже пропущенную (напр., пропустил вторник — в среду открываешь список дней недели и берёшь вторник; выполненные/пропущенные/будущие помечены статусом);
  - **Повторить прошлую** — клон последней тренировки как стартовая точка;
  - **Свободная** — с нуля, без плана.
- **Активная сессия:** список добавленных подходов, поле ввода внизу.
  - Ввод свободным текстом, как в боте: `Жим штанги 80×10`, `Подтягивания 10 8 7`, `Планка 60 секунд`, суперсеты, «до отказа».
  - Голосовой ввод (микрофон → Whisper → тот же парсер).
  - Подсказка прошлого результата по упражнению («в прошлый раз 80×8»).
  - Редактирование/удаление подхода, заметка к подходу.
- **Завершение:** ИИ-резюме тренера (тоннаж, динамика к прошлой такой же тренировке, прогресс по упражнениям).

#### 3.3.1 Выбор упражнения из текущей тренировки

Каждое упражнение в активной сессии — тапабельное. Тап открывает карточку упражнения (bottom sheet) с тремя действиями:

1. **Быстрый подход.** Когда добавляешь подход, приложение сразу предлагает целевое значение:
   - если упражнение есть в плане на сегодня — подставляется плановое (например, `82.5×8`);
   - если плана нет — рекомендация из истории (`recommendation_from_history`).

   Предложение показано крупно, прямо в большом поле. Править значение можно двумя способами: **стрелки вверх/вниз** для быстрой подгонки (шаг веса, напр. 2.5 кг) и **тап по самому числу** — он ставит курсор и открывает цифровую клавиатуру для прямого ввода точного значения. Это работает для всех числовых полей (вес, повторы, минуты, секунды). Один тап «Подтвердить» — и подход записан. Ниже одно текстовое поле «ввести другое» со значком микрофона справа — пишешь `80×10` или диктуешь голосом (Whisper → парсер). Название упражнения уже подставлено, повторно его вводить не нужно.
2. **Правка/удаление подходов.** Список подходов этого упражнения с возможностью отредактировать вес/повторы/заметку или удалить (`PATCH /sets/{id}`, `DELETE /sets/{id}`).
3. **История упражнения.** Прошлые результаты и динамика («в прошлый раз 80×8», рекомендация по весу) — на базе существующего модуля `exercise_history` (`format_exercise_history`, `recommendation_from_history`).

#### 3.3.2 Добавление упражнения — выбором, а не печатью

Во время тренировки печатать неудобно, поэтому ввод текстом — не основной способ:

1. **По плану ничего добавлять не нужно.** Если тренировка запущена из плана, все упражнения уже подгружены как чеклист: выполненные отмечены галочкой, следующее подсвечено, остальные — серым с целью (подходы×повторы×вес). Тапаешь упражнение → открывается его карточка с предложенным подходом. Никакого ввода названий.
2. **Добавить сверх плана — выбор из списка.** Кнопка «Добавить упражнение» открывает пикер с вкладками:
   - **Недавние** — то, что делал в последнее время, добавляется одним тапом (плюс-иконка). Покрывает 90% случаев.
   - **По группам** — каталог по группам мышц (Грудь, Спина, Ноги, Руки, Плечи…), внутри список упражнений, тап = добавить.
   - **Все** — полный каталог.
3. **Поиск/голос — внизу как опция.** Строка поиска с микрофоном остаётся для быстрого шортката, но это запасной путь, а не главный. При вводе подставляются совпадения из каталога (`exercise_normalizer.possible_matches`) с нормализацией названий (`exercise_catalog`), чтобы не плодить дубли.

Источники для пикера: недавние/частые из истории, каталог по группам мышц, и текущий план — всё выбирается тапом.

#### 3.3.3 Типы подходов — поле подстраивается под упражнение

Тип упражнения известен из каталога, поэтому поле ввода подхода меняется автоматически (в БД уже есть `weight_kg`, `reps`, `duration_seconds`, `reps_text`):

- **Силовое (вес × повторы)** — два степпера: вес и повторы. Базовый случай.
- **По времени (планка, велосипед, кардио)** — степпер времени `мин:сек` (шаг секунд — 10, минут — 1; точное значение добивается тапом по числу) + кнопка **«Запустить таймер»**: можно засечь подход прямо в приложении, по «Стоп» результат подставляется в `duration_seconds`.
- **С весом тела (подтягивания, отжимания)** — только степпер повторов, с переключателем **«+ доп. вес»** для работы с поясом/отягощением.

Если тип упражнения неоднозначный (напр. «велосипед» — на время или на повторы), при первом добавлении предлагается выбрать формат один раз, дальше он запоминается для этого упражнения.

#### 3.3.4 Полный цикл выполнения тренировки

**Старт — 4 варианта:** по плану на сегодня; другой день недели (взять пропущенный); повторить прошлую (клон); свободная (с нуля). В первых трёх упражнения подгружаются сразу.

**Цикл подхода (повторяется до конца упражнения):** тап по упражнению → карточка → ввод подхода (стрелки/тап по числу) → «Подтвердить» → автоматически запускается **таймер отдыха** (новая фишка приложения, в боте её нет; кнопки «+30 сек» / «Пропустить», по нулю — мягкое уведомление) → следующий подход. Когда цели упражнения выполнены — оно отмечается ✓, подсветка уходит на следующее.

**Спецподходы (теги при вводе):**
- *Разминка* — помечается значком, не идёт в рабочий тоннаж и расчёт прогресса.
- *До отказа / AMRAP* — пишется в `reps_text`, после подхода уточняется фактическое число повторов.
- *Суперсет* — связывает текущее упражнение с выбранным в группу (`superset_group`), отдых считается только после пары.

**Жизненный цикл:** тренировка хранится на сервере, поэтому её можно свернуть и продолжить позже — на главной появляется баннер «Незавершённая тренировка → Продолжить» (на базе `get_active_workout`). Меню «···» даёт: заметку к тренировке (текст/голос, попадает в ИИ-резюме), сворачивание, удаление.

**Завершение:** «Завершить» → ИИ-резюме тренера (тоннаж, динамика, новые рабочие веса, учёт заметки) → «Готово» / «Поделиться».

### 3.4 Планы

Раздел из четырёх задач:

1. **Обзор недели.** Список Пн–Вс, сегодняшний день выделен. У каждого дня статус: выполнено / запланировано / пропущено / отдых.
2. **День плана.** Открываешь день → список целевых упражнений с целями (подходы × повторы × вес, напр. «Тяга штанги 4×8 · 70 кг»). Отсюда «Начать» или «Редактировать».
3. **Редактирование.** Добавить упражнение (через поиск по каталогу с автоподсказкой), задать подходы/повторы/вес, переставить порядок, удалить. Заметки к дню.
4. **ИИ-генерация.** Сгенерировать план на день или неделю на основе истории за 14 дней (`planner`), учитывая уже запланированное, чтобы не дублировать нагрузку. Результат показывается перед применением — можно перегенерировать.

### 3.5 История

1. **Лента + фильтры.** Список прошедших тренировок с фильтром по периоду (неделя / месяц / произвольный) и поиском по упражнению.
2. **Карточка тренировки.** Упражнения, подходы, заметки, длительность, тоннаж; «Повторить эту тренировку».
3. **Прогресс упражнения.** По конкретному упражнению — график рабочего веса во времени, рекорд (PR), дельта за период и список последних результатов (`exercise_history`).

### 3.6 Замеры

- **Новый замер:** форма со всеми 9 полями — **вес, голень, бедро, бедра, живот, талия, грудь, рука, шея** (точно как в боте: `weight_kg, calf_cm, thigh_cm, hips_cm, belly_cm, waist_cm, chest_cm, arm_cm, neck_cm`). Любое поле можно пропустить.
- **Ввод текстом/голосом:** «вес 82 талия 84 грудь 104» → разбор (`measurement_parser`) → подтверждение распознанного → сохранение. Незаполненные поля можно дозаполнить.
- **История:** выбираешь параметр (вес / талия / грудь / рука / …) → график динамики + таблица значений с дельтами и итогом за период.

### 3.7 Фото-прогресс (отдельный раздел)

- **Съёмка серии:** снять/выбрать несколько фото → «Готово, анализировать» (ИИ-анализ `photo_vision`) или «Загрузить без анализа».
- **Галерея серий:** сгруппированы по датам; вход в режим сравнения.
- **Сравнение до/после:** два фото рядом с датой и весом + ИИ-комментарий об изменениях. Удаление серии.

### 3.8 Отчёты (отдельный раздел)

- Выбор периода (1 нед / 2 нед / месяц / 2 мес / произвольный) и выбор, что включить (тренировки / замеры / фото).
- Генерация PDF (`report_builder`) → превью со сводкой периода → «Поделиться» (Telegram, почта, Файлы) или скачать.

### 3.9 Настройки (бывш. «Сервис»)
- Часовой пояс, очистка данных, выход.

## 4. Модель данных (уже существует в БД бота)

Переиспользуем как есть, ничего не мигрируем:

- `workouts` — тренировка (дата, фокус, заметки, активна/завершена, ссылка на план).
- `exercise_sets` — подход: `exercise_name, weight_kg, reps, reps_text, duration_seconds, superset_group, is_warmup, is_failure, notes, set_number`.
- `training_plans` / `planned_workouts` — планы и упражнения в них.
- `body_measurements` — `taken_on` + поля `weight_kg, calf_cm, thigh_cm, hips_cm, belly_cm, waist_cm, chest_cm, arm_cm, neck_cm, notes`.
- `progress_photos` — `taken_on, file_id, ai_description, notes`, объединение в серии.

Единственное изменение для приложения: фото сейчас хранятся как Telegram `file_id`. Для приложения нужно хранилище файлов (локально на сервере или S3-совместимое) — см. план работ.

## 5. API-контракт (черновик, FastAPI поверх текущего кода)

Базовый префикс `/api/v1`. Аутентификация: bearer-токен на пользователя (выдаётся при первом входе; на этапе «только для себя» — один статический токен в `.env`, как сейчас `allowed_telegram_user_id`).

### Тренировки
```
POST   /workouts                 # начать тренировку:
                                 #   { "from_plan_id": 123 }   # по плану любого дня недели (в т.ч. пропущенного)
                                 #   { "repeat_from": 456 }    # клон прошлой тренировки
                                 #   {}                        # свободная
GET    /workouts/week            # тренировки плана текущей недели со статусами (для «другого дня»)
GET    /workouts/active          # текущая активная сессия
POST   /workouts/{id}/sets       # добавить подход: { "text": "Жим 80x10" }  → разбор set_parser
GET    /workouts/{id}/sets       # подходы тренировки
PATCH  /sets/{id}                # отредактировать подход
DELETE /sets/{id}
POST   /workouts/{id}/finish     # завершить → возвращает ИИ-резюме тренера
GET    /workouts?from=&to=       # история за период
GET    /workouts/{id}            # одна тренировка
GET    /workouts/{id}/exercises  # упражнения текущей сессии (сгруппированы, со сводкой подходов)
```

### Выбор упражнения и каталог
```
GET    /exercises/recent?limit=      # недавние/частые упражнения (основной способ выбора)
GET    /exercises/catalog?group=     # каталог по группе мышц (Грудь/Спина/Ноги/Руки/Плечи…)
GET    /exercises/search?q=&limit=   # запасной путь: поиск/голос (possible_matches) + сессия + план
GET    /exercises/{key}/history?limit=  # история упражнения + рекомендация по весу
GET    /exercises/{key}/progress        # динамика рабочего веса во времени + PR (для графика прогресса)
GET    /workouts/{id}/exercises/{key}/suggestion  # целевой подход: план на сегодня → иначе рекомендация по истории
POST   /workouts/{id}/sets            # добавить подход к выбранному упражнению:
                                       #   { "exercise_key": "bench_press", "accept_suggestion": true }  # подтвердить предложенное
                                       #   { "exercise_key": "...", "text": "80x10" }                     # голос/текст
                                       #   { "exercise_key": "...", "weight_kg": 80, "reps": 10 }         # ручной ввод
```

### Планы
```
GET    /plans?from=&to=          # планы на период (обзор недели)
GET    /plans/today
GET    /plans/{id}               # день плана с целевыми упражнениями (подходы×повторы×вес)
POST   /plans                    # создать вручную
POST   /plans/{id}/exercises     # добавить упражнение в план { exercise_key, sets, reps, weight }
POST   /plans/generate           # ИИ-генерация { "scope": "day" | "week" }
PATCH  /plans/{id}
DELETE /plans/{id}
```

### Замеры
```
POST   /measurements             # { "values": {...} }  или  { "text": "вес 82 талия 84" }
GET    /measurements?limit=
GET    /measurements/last
DELETE /measurements/{id}
```

### Фото
```
POST   /photos                   # multipart upload (одно/несколько) → серия
POST   /photos/{series}/analyze  # ИИ-анализ серии
GET    /photos?limit=
PATCH  /photos/{id}              # заметка
DELETE /photos/series/{series}
```

### Отчёты и настройки
```
POST   /reports                  # { "from": ..., "to": ... } → PDF (bytes / url)
GET    /me                       # профиль, часовой пояс
PATCH  /me                       # сменить часовой пояс
POST   /me/wipe                  # очистка данных
```

Большинство эндпоинтов — это тонкие обёртки над уже существующими функциями (`add_set` + `set_parser.parse_exercise_input`, `create_measurement` + `measurement_parser`, `planner.*`, `coach.*`, `report_builder.build_period_report`).

## 6. План работ по фазам

**Фаза 0 — API-слой (бэкенд).** Добавить FastAPI-приложение рядом с ботом, переиспользуя `app/db` и `app/bot/services`. Аутентификация по токену. Файловое хранилище для фото. Это самая ценная и переносимая часть — нужна при любом выборе клиента.

**Фаза 4 — Планы и ИИ-тренер.** Генерация планов, резюме после тренировки, голосовой ввод.

**Фаза 5 (опц.) — Нативное приложение и App Store.** Перенос на SwiftUI поверх готового API, оформление, публикация ($99/год).
