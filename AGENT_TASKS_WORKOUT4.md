## W4-1 — [P0] Дубль/потеря подходов: имя строки ≠ каноническое имя при записи
Точный баг (из живого теста, тренировка id 43, подтверждён заметкой владельца):
- Добавил «**Махи в стороны стоя**» → строка с 0 подходов; записал 4×12×10 — но подходы ушли в
  ОТДЕЛЬНУЮ строку «**Махи гантелями в стороны**» (канон). Добавленная строка осталась пустой →
  визуальный дубль, подходы «не там».
- То же со «**Скамья Скотта**» (0 подх) → подходы под «Сгибания на скамье Скотта».
Причина: при добавлении упражнения в активную тренировку строка берёт имя КАК ВЫБРАНО (алиас/
легаси-имя из «Недавних»), а `submitSets` шлёт `exercise_name` = это же имя, которое бэкенд
канонизирует (`_canonical_name`/DB-5/алиасы) в ДРУГУЮ каноническую строку. Итог: подходы
привязываются к канону, а показанная строка (алиас) остаётся пустой.
- **Фикс:** при добавлении упражнения в тренировку использовать КАНОНИЧЕСКОЕ имя, совпадающее с
  тем, под которым сохранятся подходы. В `chooseEx`: если известен `key` — брать `key_to_name(key)`
  (канон каталога) как имя строки; если имя — алиас без key, но резолвится (`name_to_key`) —
  использовать канон. Тогда строка == то, что уйдёт в БД → подходы падают в неё, дубля нет.
- Дополнительно: рендер активной тренировки должен группировать подходы по РЕЗОЛВНУТОМУ
  каноническому имени (на случай, если алиас всё же попал в строку) — чтобы одинаковые
  упражнения не двоились. И добавить недостающий алиас «скамья скотта» → `preacher_curl`
  в `data/exercise_catalog_v2.json` (сейчас его нет — «Скамья Скотта» каталогу неизвестна).
- Acceptance: добавил упражнение под любым (алиасным) именем → записанные подходы попадают в ту
  же строку; в активной тренировке и истории нет пустых дублей; «Махи в стороны стоя»/«Скамья
  Скотта» больше не создают вторую строку.

## W4-2 — Bodyweight-упражнения: вес ОПЦИОНАЛЬНО (сейчас поля веса нет совсем)
Владелец: «в части упражнений нет веса». В каталоге 30 упражнений `input=bodyweight` — у них поле
веса СКРЫТО полностью. Но многие делают С доп.весом: **подтягивания, отжимания на брусьях,
гиперэкстензия, подтягивания широким/обратным хватом** и т.п. (пояс с весом).
- Фикс: для `bodyweight` показывать поле веса как **опциональное** (можно оставить пустым →
  запись как «своим весом»; можно ввести доп.вес). Повторы обязательны, вес — необязателен.
  Применить в аккордеоне (`setInputRow`/`confirmSets`), редакторе плана и архив-композере.
- (Опц., на усмотрение) в каталоге можно ввести различие «чисто телесные» (пресс/кор — вес не
  нужен) vs «телесные, часто с весом» (подтягивания/брусья/гипер) — но проще: у ВСЕХ bodyweight
  вес опционален.
- Acceptance: у подтягиваний/брусьев/гиперэкстензии есть необязательное поле веса; чисто телесные
  можно записать без веса; ничего не сломано для strength/time.

## W4-5 — «кг» на строке ЗАПИСАННЫХ подходов (не только на «цели»)
На скрине владельца записанные подходы показаны как «25×12 · 25×12 · …» — без «кг». W2-5
подписал единицу только на строке «цель»/`exLine`, а сводка записанных подходов (`setLabel`,
`web/app.js:~357`) рендерит `fmt(weight)+'×'+reps` без единицы.
- Фикс: в `setLabel` (и везде, где показывается вес записанного подхода) подписывать вес «кг».
  Формат на усмотрение, но без двусмысленности: напр. «25 кг × 12» на подход, либо при
  одинаковых подходах — свернуть в «4 × 12 · 25 кг». Кардио/время — «мин:сек», bodyweight без
  веса — только повторы; вес с единицей — там где вес есть.
- Acceptance: в списке записанных подходов у веса есть «кг»; нигде вес не идёт голой цифрой.

## W4-6 — «Скамья Скотта · цель 4×12» без веса (данные/поле)
Часть упражнений показывают цель без веса. Два источника: (1) в плане у упражнения не задан
`target_weight` (тогда «цель 4×12» — это ок, вес не обязателен на цели), (2) если упражнение
силовое, поле веса при ЛОГИРОВАНИИ должно быть всегда (strength → вес×повт). Проверить, что ни
одно силовое не остаётся без возможности ввести вес (пересечение с W3-1 «тип из каталога» и W4-2
«bodyweight — вес опционально»). Отдельного acceptance не нужно, если W3-1+W4-2 закрывают — тогда
пометить как покрытое.

## W4-7 — [P0-корень] Расклеить каталог: разные упражнения ≠ один канон (алиасы-подмена)
КОРЕНЬ подмены «махи в кроссовере → махи гантелями»: при курировании в каталог налеплены
алиасы, склеивающие РАЗНЫЕ упражнения. Разное оборудование = разные упражнения (свой прогресс/
история): «Махи гантелями в стороны» ≠ «Махи в кроссовере» ≠ «Махи в тренажёре»; «Скамья Скотта»
(как отдельное) ≠ «Сгибания на скамье Скотта»; тяги/сведения/жимы «в тренажёре»/«в кроссовере»/
«в Смите» — отдельные позиции, а не алиасы гантельных/штанговых.
- Задача: пройти `data/exercise_catalog_v2.json`, найти алиасы, которые на деле — ОТДЕЛЬНОЕ
  упражнение (маркеры оборудования: «кроссовер», «в тренажёре», «в Смите», «гакк», «гравитрон»,
  «канат», «машина», «хаммер», «блок», и т.п.), и **вынести их в самостоятельные записи**
  (canonical + группа + input + по возможности картинка). Убрать эти строки из `aliases`
  соответствующих гантельных/штанговых упражнений. Оставлять алиасами ТОЛЬКО настоящие синонимы
  (орфография/раскладка/сокращения), НЕ смену снаряда.
- Ассистент подготовит список кандидатов-на-расклейку (алиасы с маркером оборудования) и приложит
  сюда; Code применяет к каталогу. Если для нового упражнения нет картинки в источнике — можно без
  картинки (плейсхолдер), это не блокер.
- **Совместимость:** это НЕ ломает историю — старые записи по-прежнему резолвятся (их имя станет
  каноном новой записи или останется алиасом верной). Проверить, что 0 осиротевших.
- Acceptance: «кроссовер/тренажёр/Смит»-варианты — отдельные упражнения в пикере и в каталоге;
  импорт/лог больше НЕ подменяет их гантельным каноном; история цела.

**Кандидаты (проверено ассистентом, 13 алиасов с маркером оборудования):**
- **ОБЯЗАТЕЛЬНО расклеить (реальная подмена, снаряд отличается от канона):**
  • «махи одной рукой в кроссовере» сейчас алиас «Махи гантелями в стороны» → ВЫНЕСТИ отдельное
    «**Махи в кроссовере**» (shoulders). ← это ровно баг владельца.
- **НЕ трогать (законные синонимы — канон уже тот же снаряд):** «обратный pec dec» / «обратная
  бабочка» → «Разведение в тренажёре (задняя дельта)»; «бабочка / pec deck» → «Сведение в
  тренажёре (бабочка)»; «тяга в тренажёре с упором …» → «Рычажная тяга с упором». Это один и тот

- **На усмотрение (пограничные, снаряд ~совпадает):** «подъём на носки в тренажёре» →
  «Подъём на носки стоя»; «хип-траст/ягодичный мост в тренажёре» → «Хип-траст». Можно оставить
  алиасами; расклеивать по желанию.

## W4-8 — Импорт/лог: НЕ подставлять канон молча (довести DB-7 до импорта)
