## W3-1 — Тип упражнения брать из каталога, а не из regex (гравитрон без веса — баг)
«Подтягивания в гравитроне» показывается БЕЗ поля веса (как bodyweight), хотя это тренажёр с
(противо)весом. Причина: `chooseEx` (`web/app.js:648-649`) определяет тип хрупким regex
(`/подтяг|отжим|брус/ → bodyweight`, `/план|велосипед|кардио/ → time`). Из-за «подтяг» гравитрон
попадает в bodyweight.
- Фикс: тип упражнения брать из **каталога** (авторитетно), а не угадывать regex. Бэкенд уже
  умеет `exercise_type(name,key)` (`api/main.py:108`) и отдаёт тип в каталоге — прокинуть `type`
  в записи пикера/каталога (`/exercises/catalog|search|recent`) и использовать его во фронте
  (chooseEx/openAddSet), убрав regex-угадайку.
- Гравитрон/ассистированные тренажёры = силовое с весом (вес = вес противовеса/нагрузки).
- Acceptance: гравитрон и прочие тренажёрные — с полем веса; тип берётся из каталога, не из
  подстроки названия.

## W3-2 — Поиск по КАЖДОМУ слову упражнения (не только первое/префикс)
Владелец: поиск должен находить по любому слову («гравитрон» → «Подтягивания в гравитроне»).
NB: серверный `/exercises/search` (`_catalog_search`) уже матчит по подстроке (в проверке
находит «гравитрон»); вероятно, у пользователя был **старый закэшированный фронт**. Тем не менее
усилить и гарантировать:
- Поиск матчит по КАЖДОМУ слову-токену запроса против канонического имени И всех алиасов
  (по подстроке/префиксу токена, регистронезависимо), не только по первому слову/началу строки.
  Мультисловный запрос — все токены должны встретиться (AND) в любом порядке.
- Убедиться, что фронт-пикер (`pickSearch`, `planSearch`, `rPickTab` поиск, если есть) ходит в
  обновлённый `/search`. Поднять sw, чтобы разошёлся свежий фронт.
- Acceptance: поиск по слову из середины названия находит упражнение; мультислово работает; на
  проде (после bump sw) «гравитрон» находит «Подтягивания в гравитроне».

## W3-3 — Редактирование подхода: подставлять записанные значения, а не нули
`editSet` (`web/app.js:598-605`) строит форму с нулями (`stepRow([['weight',0,…],['reps',0,…]])`),
теряя текущие значения подхода. Надо префилл из реально записанного подхода.
- Фикс: найти подход по `sid` в `window._WO` (или прокинуть значения в `editSet`) и предзаполнить
  вес/повторы/длительность + флаги (разминка/до отказа). Поля editable (+ W2-2 select-on-focus).
- Acceptance: открыл редактирование подхода → видны его текущие вес/повторы (не нули) → правка
  сохраняется.

## W3-4 — Вернуть комментарий К УПРАЖНЕНИЮ (не к подходам)
Пропал комментарий/заметка на уровне упражнения в активной тренировке. К подходам заметка НЕ
нужна — только к упражнению.
- Фикс: в раскрытом упражнении (аккордеон, W2-1) добавить поле «Заметка к упражнению»
  (сохранять на упражнение workout'а). Если бэкенд-хранилище заметки упражнения отсутствует —
  использовать имеющееся (в плане `ex.notes` уже есть; для активной тренировки — где хранится
  заметка упражнения: проверить модель `exercise_sets`/workout exercises; при отсутствии — минимально
  добавить). Per-set заметки убрать/не показывать в этом контексте.
- Acceptance: у упражнения в активной тренировке есть редактируемая заметка; сохраняется и видна
  при возврате; к отдельным подходам поля заметки нет.

## W3-5 — «Сегодня выполнено» и в меню «Тренировка» (как на Главной)
На Главной после завершения сегодняшней тренировки — зелёный статус «выполнено» (W2-6). В хабе
**«Тренировка»** этого нет. Сделать так же: если за сегодня есть завершённая тренировка —
показать в хабе «Тренировка» зелёную отметку «Сегодня выполнено» (и/или у пункта старта), а не
предлагать начать как ни в чём не бывало. Переиспользовать `today_done` из дашборда/эндпоинта.
- Acceptance: выполнил тренировку → в «Тренировка» видно «сегодня выполнено» (зелёным), консистентно
  с Главной.

## W3-6 — Аудит ВСЕХ упражнений: типы и разумные дефолты (бег 20×10 — абсурд)
«Бег на дорожке» предлагает «20 по 10» (подходы×повторы) — бессмыслица для кардио. Провести
аудит всего каталога (186):
- Каждому упражнению — корректный **тип ввода**: `cardio`/бег/ходьба/эллипс/гребля/степпер/
  скакалка → **время (и/или дистанция)**, НЕ подходы×повторы×вес; планка/вис → время;
  подтягивания/отжимания/брусья (без доп.веса) → bodyweight (повторы, вес опционально);
  тренажёры с нагрузкой (гравитрон и т.п.) → силовое с весом; остальное силовое → вес×повторы.
- Дефолтные цели при добавлении в план/тренировку — вменяемые по типу (кардио → напр. 20 мин, не
  «20×10»; сила → 3–4×8–12). Проверить, что план-редактор, AI-коуч и архив-импорт НЕ навешивают
  подходы×повторы на кардио.
- Свериться с `exercise_type()` (`api/main.py:108`) — расширить/поправить, чтобы покрывал все
  кардио/функциональные из нового каталога (не только «планк»/«велосипед»). Лучше — тип/режим
  хранить в самом каталоге (`data/exercise_catalog_v2.json`, поле `input`/`kind` на упражнение)
  и брать оттуда.
- Acceptance: ни одно кардио не предлагает подходы×повторы×вес; у каждого упражнения корректный
  режим ввода и разумные дефолты; бег/ходьба/эллипс — время.

## W3-7 — PDF-отчёт из Истории: битые символы (кириллица)
Веб-отчёт PDF выходит с «битыми» символами. Причина: `report_builder._register_fonts`
(`app/bot/services/report_builder.py:55-78`) ищет DejaVuSans по системным путям и при отсутствии
откатывается на **Helvetica** (без кириллицы). В API-контейнере, судя по всему, шрифта нет.
- Фикс: гарантировать кириллический TTF в API-образе — либо `apt-get install -y fonts-dejavu-core`
  в `Dockerfile.api`, либо (надёжнее, как с `data/`) **забандлить TTF в репозиторий** (напр.
  `assets/fonts/DejaVuSans.ttf` + Bold) и добавить этот путь ПЕРВЫМ в `candidates`, скопировав
  `assets/` в образ (`COPY`). Проверить, что веб-`/api/reports` PDF рендерит кириллицу.
- Acceptance: PDF-отчёт из Истории — кириллица читаема, без битых символов, на проде.
